# Ensembly (AI 회의실)

여러 AI가 A2A로 모여(assembly) 의견을 합치는(ensemble) 토론 회의실입니다.

토론 주제를 적으면, 서로 다른 회사의 AI들이 A2A로 연결되어 회의를 하고 결론을 정리합니다.
주제는 무엇이든 됩니다. 찬반 토론("공공기관에 주 4일제를 도입해야 할까?"), 아이디어 회의, 의사결정, 자료 검토("첨부한 제안서 초안에서 보완할 점은?") 모두 같은 화면에서 합니다.
참고할 자료(PDF, HWPX, Word, Excel 등)는 선택으로 첨부하고, 자료마다 설명을 달 수 있습니다.
각 에이전트는 자기 명함(Agent Card), 자기 모델, 자기 기억을 따로 가집니다. 기본은 사회자와 참석자 5명(최대 인원), 12턴이며 설정에서 참석자(2~5명)와 턴 수를 바꿀 수 있습니다.

| 에이전트 | 역할 | 기본 모델 |
|---|---|---|
| 사회자 | 발언 순서를 정하고 결론을 정리 | Gemini (`google/gemini-3-flash-preview`) |
| 민서 | 깐깐한 검증가: 주장의 근거, 사실관계, 숫자와 계산 | Claude (`anthropic/claude-sonnet-5`) |
| 나래 | 큰 그림 전략가: 목표, 핵심 쟁점, 우선순위, 대안 | GPT (`openai/gpt-5.5`) |
| 도윤 | 공감 대변인: 실제로 영향을 받는 사람의 이해와 체감, 오해 소지 | Solar (`upstage/solar-pro4`) |
| 현우 | 논리 점검가: 정의, 숨은 전제, 비교의 공정성, 인과 비약 | Gemini (`google/gemini-3-flash-preview`) |
| 하율 | 리스크 담당: 실행 리스크, 반발과 이해관계, 반대편 시각 | Grok (`x-ai/grok-4.20`) |

모델은 웹 화면의 설정에서 바꿀 수 있어요. OpenRouter 목록에서 18개 회사의 대화 모델을 회사별 최신순으로 보여 주고,
지원 종료(예정) 모델, 배치·무료·검색·코딩 전용·이미지/음성 모델, 문맥이 짧은 모델, 출력 100만 토큰당 30달러가 넘는 모델은 목록에서 뺍니다(`api/models.js`).

## 회의 진행 (기본 12턴)

| 턴 | 단계 | 내용 |
|---|---|---|
| 1~5 | 1라운드 | 다섯 명이 한 번씩 첫 의견. 누가 누구에게 질문하면 사회자가 그 사람을 다음으로 부릅니다 |
| 6~10 | 2라운드 | 다섯 명이 한 번씩 반론과 보완. 앞사람 발언을 짚으며 시작합니다 |
| 11 | 최종 반론 | 모이는 의견과 시각이 가장 다른 두 명 중 한 명이 마지막으로 다른 시각을 한 번 더 냅니다 |
| 12 | 결론 | 사회자가 결론(판정, 핵심 결론과 제안, 우려와 반대 의견, 합의된 점, 남은 질문)을 정리합니다 |

사회자는 순서를 기계적으로 돌리지 않습니다. 1라운드는 사회자가 여는 말만 하고 끼어들지 않은 채 모두가 차례로 첫 의견을 말합니다(나도 참여 중이면 2라운드 전에 내 첫 생각도 물어봐요). 2라운드부터는 질문을 받은 사람, 직전 발언과 시각이 다른 사람, 한동안 말하지 못한 사람 등을 보고
누구에게 발언권을 줄지 정합니다(같은 사람을 연달아 부르지 않고, 한 사람이 독차지하지 않게). 차례마다 다룰 **쟁점**을 정해 탁자와 회의록, 상황판에 보여 주고,
라운드 첫 차례에는 지금까지 흐름을 짚고 이번 라운드에서 할 일을 소개합니다.

턴을 늘리면 2라운드부터 라운드마다 성격이 바뀝니다: 반박 타임 → 대안 타임(해법 내놓기) → 입장 바꿔 보기(가장 다른 시각을 대신 변호) → 합의점 찾기 → 실행 계획, 그다음은 다시 반박부터.

11번째 턴은 회의가 다수 의견으로 쏠린 채 끝나지 않도록, 결론 직전에 가장 반대하는 사람의 말을 한 번 더 듣는 장치입니다.

참석자 수나 턴 수를 바꾸면 같은 규칙으로 다시 짭니다. 마지막 1턴은 결론, 그 앞 1턴은 최종 반론(턴이 참석자 수 + 2 이상일 때),
나머지는 라운드마다 모두 한 번씩 말하는 식으로 채웁니다. 권장값은 참석자 수 × 2 + 2이고, 최소는 참석자 수 + 1, 최대 30턴입니다.

발언마다 속마음(그 순간의 판단과 다른 참석자에 대한 생각)이 함께 화면에 보입니다.
발언마다 **한 줄 입장**(예: '시범 도입부터', '시뮬레이션은 아닐 듯')과, 지금 모이는 의견과 비교한 **방향**(같은 방향 · 다른 시각 · 고민 중),
그 입장을 **얼마나 확신하는지**(%)가 함께 붙습니다. 찬반이 딱 갈리지 않는 아이디어 회의나 열린 질문에서도 쓸 수 있게 한 방식입니다.
속마음은 화면에만 보이고 다른 참석자에게는 전달되지 않으며, 에이전트마다 자기 기억은 자기 키로 암호화한 토큰으로 따로 이어집니다.

## 회의가 끊겼을 때, 회의가 끝난 뒤

- **끊긴 곳부터 이어서**: 인터넷이 끊기거나 API 키가 만료돼 응답을 못 받으면, 회의를 지우지 않고 그 턴에서 멈춥니다.
  탁자와 상단 버튼의 '이어서 진행'을 누르면 멈춘 턴부터 다시 합니다. 끝까지 성공한 턴만 기록에 남기 때문에 같은 발언이 두 번 쌓이지 않습니다.
  진행 상황은 브라우저에 저장돼서, 창을 닫았다 다시 열어도 멈춘 회의를 불러옵니다. 키 문제라면 '설정 열기'로 키를 고친 뒤 이어서 진행하면 됩니다.
- **나도 참여 (선택)**: 기본은 에이전트끼리만 토론합니다. 설정의 '나도 참여'나 탁자의 '나도 참여하기'를 켜면,
  사회자가 내 경험이나 생각이 필요하다고 볼 때(라운드마다 한 번까지) 나에게 질문하고, 참석자도 나에게 물을 수 있습니다.
  질문이 오면 회의록 아래에 질문과 답 칸이 뜨고, 답하거나 '이번엔 넘기기'를 누르면 이어서 진행됩니다. 질문이 없어도 '말하기'로 한마디씩 끼어들 수 있습니다.
  '내 프로필 카드'에 이름·역할·소개·MBTI를 적으면 에이전트들이 나를 알고 이야기합니다(모두 선택, 비우면 '나'로 참여).
  참여하면 나도 에이전트처럼 테이블에 자리가 생기고 같은 형식의 카드를 가집니다. 자리는 사회자 포함 6개라, 이때 에이전트 참석자는 최대 4명입니다.
  회의 중에는 빠른 반응(👍 동의해요, 🤔 근거가 궁금해요 등)과 '✋ 발언 신청'을 쓸 수 있고, 손을 들면 다음 차례에 사회자가 먼저 불러 줍니다.
  내가 말한 순간은 상황판에 내 칸으로 남아요.
- **자료·요청 추가 (회의 중)**: 회의가 진행 중이거나 멈춘 상태에서 탁자의 '자료·요청 추가'로 새 요청이나 자료를 넣으면,
  다음 발언부터 모든 참석자가 함께 보고 토론합니다. 회의록에는 '나 · 추가 요청'으로 남고, 추가 자료는 처음 자료보다 앞에 넣어 길어도 잘리지 않게 합니다.
- **추가 회의 (회의가 끝난 뒤)**: 탁자의 '추가 회의'나 질문 칸 아래 링크로 새 요청·자료를 넣고 한 바퀴(참석자 수 + 1턴) 또는 두 바퀴를 고르면,
  앞선 회의록과 결론을 이어받아 다시 토론하고 사회자가 결론을 새로 정리합니다(2차 결론, 앞선 결론은 결론 탭에서 펼쳐 볼 수 있음).
  공용 키로는 추가 회의를 한 번까지 할 수 있고, 턴 수 제한은 회차마다 따로 셉니다.
- **후속 질문**: 회의가 끝나면 회의록 아래에 질문 칸이 생깁니다. 기본은 사회자에게 묻고, 위의 얼굴을 눌러 다른 참석자에게도 물을 수 있습니다.
  각 에이전트는 토론 주제와 자료, 회의록, 결론, 앞선 후속 질문과 자기 속마음을 보고 자기 관점으로 답합니다(A2A 스킬 `followup`). 후속 질문은 마크다운 내보내기에도 들어갑니다.
- **에이전트 카드**: 보드의 참석자를 누르면 카드처럼 생긴 프로필(타입, 기술, 특기, 능력치, 약점, 오늘 회의 기록)이 열립니다.
  카드를 뒤집으면 그 에이전트의 이번 회의 속마음과 **오늘의 배지**가 보입니다. A2A 명함(Agent Card) 원본 JSON은 카드 아래 'A2A 명함 원본 보기'로 엽니다.
  회의가 끝났다면 카드에서 바로 그 에이전트에게 질문할 수 있습니다.
- **회의 결과 공유·저장**: 결론 탭의 '링크로 공유'를 누르면 결론·회의록·속마음·상황판을 지금 화면 모습 그대로 담은 결과 페이지가 만들어지고 `/s/<id>` 링크가 생깁니다.
  '결과 페이지 저장'은 같은 페이지를 HTML 파일 한 장으로 받아요(그림 포함, 인터넷 없이도 열림). 링크 공유를 쓰려면 Vercel 프로젝트에 **Blob 저장소**를 연결해야 하고(환경변수 `BLOB_READ_WRITE_TOKEN`이 자동으로 생겨요),
  연결 전에는 링크 대신 파일로 저장됩니다. 공유 페이지는 sandbox로 보여 줘서 이 사이트에 저장된 키·설정에 접근할 수 없어요.
- **오늘의 배지**: 회의가 끝나면 사회자가 결론을 정리하면서 참석자마다(참여했다면 나에게도) 배지를 1~2개 주고 이유를 한 문장으로 남깁니다. 카드 뒷면과 결론 탭, 마크다운에 보입니다. 사회자 배지가 없는 예전 회의는 기록으로 자동으로 정합니다. 질문왕(질문 최다), 생각 전환(다른 시각→같은 방향), 소신파(끝까지 다른 시각), 마지막 한마디(최종 반론),
  수다왕(발언 분량 최다), 날카로운 지적(우려·반대 의견에 이름 최다), 아이디어 뱅크(핵심 결론·제안에 이름 최다), 합의 도우미(가장 높은 동의로 마무리).
  배지 그림은 `vendor/badges/`, 카드 뒷면 그림은 `vendor/brand/card-back.webp`입니다.
  카드에는 페르소나에 맞춘 MBTI도 붙어 있습니다: 사회자 ENFJ(선도자), 민서 ISTJ(현실주의자), 나래 ENTJ(통솔자), 도윤 ENFP(활동가), 현우 INTP(논리술사), 하율 ENTP(변론가).
  카드 내용은 `api/_lib/personas.js`의 `profile`에서 고칩니다.

## 화면 디자인

흑백 에디토리얼 프레임 위에 참석자마다 파스텔 색 블록을 얹는 Figma 계열 스타일을 기준으로 삼았습니다(getdesign.md의 Figma DESIGN.md 참고).
- 회의 보드는 점 격자 캔버스, 참석자는 색이 다른 스티커 메모, 탁자는 네이비 블록입니다.
- 발언 중인 참석자에게는 Figma 선택 상자가, 사회자가 다음 발언자를 고르면 멀티플레이어 커서가 그 사람에게 이동합니다.
- 버튼은 모두 알약형, 분류 라벨은 모노 대문자(JetBrains Mono), 본문은 Pretendard입니다. 글꼴은 `vendor/fonts`에 들어 있습니다.
- 참석자 캐릭터는 `vendor/avatars/`에 있습니다. `{id}.png`는 상반신(명함, 속마음), `{id}-face.png`는 얼굴 확대(작은 원형 아바타)용입니다.
  명함(Agent Card)의 `iconUrl`에 상반신 주소가 들어가 있어, 다른 A2A 클라이언트도 같은 캐릭터를 볼 수 있습니다.
  캐릭터를 바꾸려면 같은 파일명으로 덮어쓰면 됩니다(정사각형 PNG 권장).
- 문구는 '~해요' 체로 통일하고, 한 화면에 할 일이 하나만 보이도록(주제 정하기 → 회의 시작 → 결론 보기) 탁자 안에 다음 행동 버튼을 둡니다.

### 로고

- 여섯 친구가 꽃잎처럼 모여 가운데에 하나의 말풍선(합의한 결론)을 만든 그림이에요. Ensembly의 '모여서 하나로'를 담았어요.
- 친구들 색은 참석자 색과 같고, 회의 보드의 자리 배치도 로고와 같은 순서(위 사회자부터 시계 방향으로 나래, 도윤, 현우, 하율, 민서)예요.
- `vendor/brand/logo.png`: 헤더용(투명 배경). `logo-1024.png`: 원본 크기.
- `favicon-16/32/48.png`, 루트의 `favicon.ico`: 브라우저 탭 아이콘. `apple-touch-icon.png`: 아이폰 홈 화면(흰 바탕). `icon-512.png`: 큰 아이콘.
- 로고를 바꾸려면 같은 파일명으로 덮어쓰면 돼요.

## Vercel에 올리기

1. 이 폴더를 GitHub 저장소로 올립니다.
2. Vercel에서 New Project로 저장소를 가져옵니다. Framework Preset은 `Other`, 빌드 설정은 그대로 둡니다.
3. (선택) Settings, Environment Variables에서 아래 값을 넣습니다. 하나도 안 넣어도 동작합니다.
4. Deploy.

| 환경변수 | 설명 |
|---|---|
| `OPENROUTER_API_KEY` | 운영자의 공용 키 |
| `MEETING_PASSCODE` | 인증키. 이 값을 넣은 사람만 공용 키를 써요. 비워 두면 누구나 공용 키를 쓰니 공개 주소라면 꼭 설정 |
| `STATE_SECRET` | 개인 메모 암호화용 비밀값. 아무 긴 문자열 |
| `ALLOWED_VENDORS` | 고를 수 있는 모델 회사. 기본 18곳: OpenAI, Anthropic, Google, xAI, Upstage, DeepSeek, Mistral, Qwen, Meta Llama, Kimi, GLM, Cohere, Amazon Nova, MiniMax, Microsoft, NVIDIA, Baidu, Tencent |
| `MODEL_MODERATOR` 등 | 에이전트별 기본 모델 (`.env.example` 참고) |

## 사용하는 방법

1. 회의실 주소로 들어가 오른쪽 위 연결 상태 버튼(예: "API 키 없음, 모의 모드 | 설정")을 누릅니다.
2. 본인 OpenRouter API 키를 넣습니다. '이 탭에서만'을 고르면 탭을 닫을 때 지워집니다.
3. 필요하면 참석자를 켜고 끄거나 모델을 바꾸고, '모두 연결 테스트'로 확인합니다. 턴 수도 여기서 정합니다.
4. '주제 입력하기'에 토론 주제를 적고(자료는 선택으로 첨부) '회의 시작'.

키를 고르는 순서는 이렇습니다.

1. 웹에서 **내 API 키**를 넣었으면 그 키를 씁니다.
2. 아니면 **인증키**가 맞는 경우에만 운영자의 공용 키를 씁니다.
3. 둘 다 아니면 모의 모드로 돌아갑니다. 오류 없이 회의 흐름을 체험할 수 있습니다.

**공용 키로 회의할 때는 모델을 바꿀 수 없습니다.** 비용을 줄이려고 가벼운 모델로 진행됩니다.

| 에이전트 | 공용 키 모델 | 내 키 기본 모델 |
|---|---|---|
| 사회자 | Gemini 3 Flash | Gemini 3 Flash |
| 민서 | Claude Haiku 4.5 | Claude Sonnet 5 |
| 나래 | GPT-5 mini | GPT-5.5 |
| 도윤 | Solar Pro 4 | Solar Pro 4 |
| 현우 | Gemini 3 Flash | Gemini 3 Flash |
| 하율 | Grok 4.3 | Grok 4.20 |

모델 회사가 어떤 모델의 지원을 끝내면(OpenRouter가 404를 돌려주면) 회의가 멈추지 않도록 그 에이전트의 기본 모델로,
그것도 안 되면 `FALLBACK_MODEL`(기본 `google/gemini-3-flash-preview`)로 자동으로 바꿔 부릅니다. 실제로 쓴 모델은 응답에 함께 적힙니다.

공용 키 모델은 `SHARED_MODEL_*` 환경변수(`.env.example` 참고)로 바꿀 수 있고,
화면의 모델 칸은 잠깁니다. 화면을 우회해 모델을 지정해 보내도 서버가 무시합니다. 모델을 고르려면 내 API 키를 넣어야 합니다.

**공용 키로는 회의를 12턴까지만 할 수 있습니다.** 화면의 턴 수 상한이 12로 바뀌고, 더 긴 회의를 보내도 서버가 거절합니다.
내 API 키를 넣으면 최대 30턴까지 쓸 수 있습니다. 상한은 `SHARED_MAX_TURNS` 환경변수로 바꿀 수 있습니다.

인증키가 새어 나갔다면 Vercel에서 `MEETING_PASSCODE` 값만 바꾸고 다시 배포하면 됩니다. 코드는 고칠 필요가 없습니다. 키는 브라우저에만 보관되고, 요청할 때 이 사이트 서버를 거쳐 OpenRouter로만 전달됩니다. 서버에 저장하지 않습니다.

## 꼭 지켜 주세요

- **외부 AI에 보내도 되는 내용만 올리세요.** 주제와 자료는 OpenRouter를 거쳐 각 모델 회사로 전송됩니다. 공개 전 문서, 기밀, 개인정보가 담긴 자료는 올리면 안 됩니다.
- OpenRouter 계정의 Privacy 설정에서 학습 이용을 끄고, 데이터 보관을 하지 않는 제공자만 쓰도록 설정하는 것을 권장합니다.
- 공개 URL에 서버 키를 넣었다면 `MEETING_PASSCODE`를 반드시 설정하세요.

## 읽을 수 있는 자료

PDF(글자가 있는 PDF), HWPX, Word(.docx), Excel(.xlsx, .xls), CSV, TSV, TXT, MD, JSON.
HWP는 한글에서 HWPX나 PDF로 저장해서 올려 주세요. 스캔 이미지 PDF는 읽지 못합니다.

**자료 분량**: 자료는 합쳐서 3만 6천 자(약 20쪽)까지 넣을 수 있고, 더 크면 받지 않습니다. 에이전트가 발언할 때마다 자료를 다시 읽어서, 클수록 토큰이 많이 들기 때문입니다.
PDF는 쪽 번호를 붙여 읽기 때문에 에이전트가 "3쪽 표"처럼 위치를 짚을 수 있습니다. 여러 파일을 함께 첨부할 수 있습니다.
읽기 라이브러리와 Pretendard 글꼴은 `vendor/`에 들어 있어 외부 CDN 없이 동작합니다.

## 로컬에서 돌려 보기

Node.js 18 이상이 필요합니다.

```bash
cp .env.example .env     # 필요한 값만 채우기 (비워 두면 모의 모드)
node dev-server.mjs      # http://localhost:3000
```

API 키가 없으면 모의 모드로, 실제 모델 없이 회의 흐름 전체를 리허설할 수 있습니다.

## A2A 구조

```
GET  /api/registry                                   회의실 주소록 (에이전트 주소 목록)
GET  /agents/{id}/.well-known/agent-card.json        명함 (A2A 1.0 Agent Card)
POST /agents/{id}                                    JSON-RPC SendMessage (A2A 1.0)
GET  /api/models                                     설정 화면용 모델 목록
```

- 회의실(브라우저)이 사회자에게 다음 발언자를 묻고, 사회자가 고른 참석자에게 발언을 요청합니다.
- 공개 회의록은 모두에게 전달되지만, 각자의 기억은 에이전트별 키로 암호화된 토큰으로만 이어집니다.
  서버리스라 저장소가 없어 토큰을 회의실이 들고 다니는 방식이며, 실제 서비스라면 에이전트마다 자기 DB에 두는 부분입니다.
- 발언은 작업(Task)으로 답하고, 결론은 작업의 산출물(Artifact)로 돌려줍니다.
- API 키와 모델 선택은 A2A 메시지 본문이 아니라 HTTP 헤더(`x-openrouter-key`, `x-agent-model`)로 보내서, 회의록 JSON에 키가 남지 않습니다.
- 공식 `a2a-sdk`(Python) 클라이언트로 명함을 읽고 메시지를 보내는 것까지 확인했습니다.

## 고치고 싶을 때

- 페르소나 성격, 말투, 관심사, 카드 프로필: `api/_lib/personas.js`
- 기본 인원과 턴 규칙: `index.html`의 `ALL_MEMBERS`, `recommendedTurns`, `buildPlan`
- 발언 길이, 자료 자르는 길이: `api/a2a.js`의 `clip(...)` 숫자
- 예시 주제: `index.html`의 `EXAMPLES`

```
index.html            회의실 화면 (주제와 자료 입력, 설정, 회의 진행, 결론, 후속 질문)
```
